# Custom Frames

## Overview

`Frame.from` defines a callback that produces one signing frame or multiple unsigned frames. Use it when the built-in helpers do not express your call or validation logic.

## Recipes

### Define an Unsigned Frame

```ts twoslash
import { Frame } from 'viem/frames'

const frame = Frame.from(() => ({ // [!code focus]
  frame: { mode: 'sender', value: 1n }, // [!code focus]
})) // [!code focus]
```

### Declare a Signature

The example assumes a deployed account contract implements `validate(uint256)`, checks the referenced signature, and performs the required approvals. Use that contract's address as the transaction account.

:::code-group

```ts twoslash [example.ts]
import { encodeFunctionData, parseAbi } from 'viem'
import { Frame } from 'viem/frames'
import { account } from './viem.config'

// This ABI is illustrative; use your deployed account's validation ABI.
const abi = parseAbi(['function validate(uint256 signatureIndex)'])
const frame = Frame.from(({ signatureIndex }) => ({ // [!code focus]
  frame: { // [!code focus]
    mode: 'verify', // [!code focus]
    flags: 'approveExecutionAndPayment', // [!code focus]
    data: encodeFunctionData({ abi, functionName: 'validate', args: [BigInt(signatureIndex)] }), // [!code focus]
  }, // [!code focus]
  signatures: [{ // [!code focus]
    scheme: 'secp256k1', // [!code focus]
    signer: account.address, // [!code focus]
    sign: ({ hash }) => account.sign({ hash }), // [!code focus]
  }], // [!code focus]
})) // [!code focus]
```

```ts twoslash [viem.config.ts] filename="viem.config.ts"
// [!include ~/snippets/frames/viem.config.ts:setup]
```

:::

:::info
Supplying [approval flags](/docs/frames/raw-frames#flags) only permits approval; it does not perform it.
:::
## `Frame.from`

Creates a helper whose callback runs during frame preparation.

### Usage

```ts twoslash
import { Frame } from 'viem/frames'

const frame = Frame.from(() => ({ // [!code focus]
  frame: { mode: 'sender', value: 1n }, // [!code focus]
})) // [!code focus]
```

### Parameters

#### definition

- **Type:** `Frame.Definition`

A synchronous callback receiving `{ frames, signatureIndex }`. `frames` contains peer frames, and `signatureIndex` is the first global signature slot allocated to this helper. Return `{ frame, signatures? }` or `{ frames }`; multi-frame results cannot declare signatures.

```ts twoslash
import { Frame } from 'viem/frames'

const frame = Frame.from(() => ({
  frames: [{ mode: 'sender', value: 1n }, { mode: 'sender', value: 2n }], // [!code focus]
}))
```


Preparation may invoke the callback again after expanding peers. Keep it free of signing and other side effects. Its return shape and signature metadata must remain stable between passes. Returned frames use the [raw frame fields](/docs/frames/raw-frames), including `mode` and `flags`.

### Return Value

`Frame`

An unresolved helper retaining its callback. Pass it to transaction actions; do not serialize the helper object as JSON.

### Errors

| Error | Condition |
| --- | --- |
| `BaseError` | Preparation changes its return shape or allocated signature entries, or a signature entry has no signing callback. |

## `Frame.Definition`

The callback type accepted by `Frame.from`. It receives a readonly array of peer frames and a numeric signature index, and returns either a single frame with optional signatures or a readonly array of unsigned frames.

## `Frame.Signature`

A signature declaration paired with a `sign` callback. `scheme`, `signer`, and optional `payload` describe the entry. Supported schemes are `secp256k1`, `p256`, and `arbitrary`; signer requirements depend on the scheme.

`sign({ hash, signatureIndex, transaction })` returns a promise of signature bytes or a supported signature object. `hash` is the entry’s nonempty custom `payload`, or the canonical transaction signing hash when no custom payload is provided. Explicit payload signatures are finalized before the canonical hash is computed. The callback receives its own global index, so no separate signature array needs to be aligned.

Declare signatures through helpers rather than also supplying a transaction-level signature array. Signing and preparation errors propagate to the caller.
