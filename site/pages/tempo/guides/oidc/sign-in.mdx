# Sign In with an Identity Provider

## Overview

Your app creates an access key on the user's device, then signs the user in with a nonce that
commits to that key. [`oidc.prove`](/tempo/actions/oidc.prove) proves the ID token through the
Relay API and returns a credential for [`Account.fromZk`](/tempo/accounts/account.fromZk).

The credential authorizes the access key once, in the key's first transaction. From then on, the
access key signs for the account until it expires. The user signs in again only to authorize a
new key, such as on another device.

[See the OIDC Signers specification](https://tips.sh/1130-1)

## Recipes

These recipes assume you have registered an OAuth client with your identity provider, and that
your client connects to a [Relay API](/tempo/guides/oidc/relay-api).

### Sign In

Create a [WebCrypto key pair](/tempo/accounts/account.fromWebCryptoP256) as the access key: its
private key cannot be exported. Pass its public key to `oidc.prove` with `getToken`, which signs
the user in with the nonce, here with [Sign In with Google](https://developers.google.com/identity/gsi/web).

:::code-group

```ts twoslash [example.ts]
import { Account, WebCryptoP256 } from 'viem/tempo'
import { client } from './viem.config'

// Signs the user in with Google and returns the ID token for `nonce`.
declare function signInWithGoogle(options: { nonce: string }): Promise<string>

// 1. Create an access key on the device.
const keyPair = await WebCryptoP256.createKeyPair()

// 2. Sign in, and prove the sign-in for the access key.
const { credential } = await client.oidc.prove({ // [!code focus]
  getToken: ({ nonce }) => signInWithGoogle({ nonce }), // [!code focus]
  publicKey: keyPair.publicKey, // [!code focus]
}) // [!code focus]

// 3. Instantiate the account and its access key.
const account = Account.fromZk(credential) // [!code focus]
const accessKey = Account.fromWebCryptoP256(keyPair, { access: account }) // [!code focus]
```

### Send the First Transaction

Sign a key authorization with the account, and attach it to the access key's first transaction.
A new account holds no funds, so the Relay API pays the fee with `feePayer: true`. Later
transactions need only the access key.

:::code-group

```ts twoslash [example.ts]
import { Account, Expiry, WebCryptoP256 } from 'viem/tempo'
import { client } from './viem.config'

declare function signInWithGoogle(options: { nonce: string }): Promise<string>

const keyPair = await WebCryptoP256.createKeyPair()
const { credential } = await client.oidc.prove({
  getToken: ({ nonce }) => signInWithGoogle({ nonce }),
  publicKey: keyPair.publicKey,
})
const account = Account.fromZk(credential)
const accessKey = Account.fromWebCryptoP256(keyPair, { access: account })

// 1. Sign the key authorization with the account.
const keyAuthorization = await account.signKeyAuthorization(accessKey, { // [!code focus]
  chainId: BigInt(client.chain.id), // [!code focus]
  expiry: Expiry.days(30), // [!code focus]
}) // [!code focus]

// 2. Attach it to the access key's first transaction.
const receipt = await client.sendTransactionSync({ // [!code focus]
  account: accessKey, // [!code focus]
  calls: [{ to: '0xcafebabecafebabecafebabecafebabecafebabe' }], // [!code focus]
  feePayer: true, // [!code focus]
  keyAuthorization, // [!code focus]
}) // [!code focus]
```

:::

:::warning
The credential expires 9 minutes after the nonce is prepared. Once it expires, signing the
authorization throws `ZkCredentialExpiredError`, and the user must sign in again.
:::

### Sign In with a Redirect

Pages that redirect to the identity provider lose their state. Prepare the nonce with
`Oidc.prepare` before the redirect, and keep the result with the key pair. After the redirect,
pass the prepared fields to `oidc.prove` with the returned ID token.

:::code-group

```ts twoslash [sign-in.ts]
import { Oidc, WebCryptoP256 } from 'viem/tempo'
import { store } from './store'

// Redirects to Google with `nonce`.
declare function redirectToGoogle(options: { nonce: string }): void

const keyPair = await WebCryptoP256.createKeyPair()
const prepared = Oidc.prepare({ publicKey: keyPair.publicKey }) // [!code focus]
await store.set({ keyPair, prepared }) // [!code focus]

redirectToGoogle({ nonce: prepared.nonce }) // [!code focus]
```

```ts twoslash [callback.ts]
import { Account } from 'viem/tempo'
import { store } from './store'
import { client } from './viem.config'

// The ID token Google returned to the redirect URI.
declare const token: string

const { keyPair, prepared } = await store.get() // [!code focus]
const { credential } = await client.oidc.prove({ ...prepared, token }) // [!code focus]

const account = Account.fromZk(credential)
const accessKey = Account.fromWebCryptoP256(keyPair, { access: account })
```

```ts twoslash [store.ts] filename="store.ts"
import type { Oidc, WebCryptoP256 } from 'viem/tempo'

type SignIn = {
  keyPair: Awaited<ReturnType<typeof WebCryptoP256.createKeyPair>>
  prepared: Oidc.prepare.ReturnType
}

/** Keeps the sign-in across the redirect, such as in IndexedDB. */
export declare const store: {
  get(): Promise<SignIn>
  set(value: SignIn): Promise<void>
}
```

key's address.

### Restore the Account on Later Visits

An authorized access key keeps signing until its expiry, so later visits need no sign-in. Keep
the key pair and the account's address after signing in, then pass the address as `access` to
rebuild the access key.

:::code-group

```ts twoslash [example.ts]
import type { Address } from 'viem'
import { Account, type WebCryptoP256 } from 'viem/tempo'
import { client } from './viem.config'

// Saved after signing in.
declare const address: Address
declare const keyPair: Awaited<ReturnType<typeof WebCryptoP256.createKeyPair>>

const accessKey = Account.fromWebCryptoP256(keyPair, { access: address }) // [!code focus]

const receipt = await client.sendTransactionSync({
  account: accessKey,
  calls: [{ to: '0xcafebabecafebabecafebabecafebabecafebabe' }],
  feePayer: true,
})
```

### Authorize More Access Keys

A credential authorizes one access key. Authorize it as an admin key to add keys later, such as
on another device, without signing in again. The admin key then authorizes other keys with
[`accessKey.signAuthorization`](/tempo/actions/accessKey.signAuthorization).

:::code-group

```ts twoslash [example.ts]
import { Account, WebCryptoP256 } from 'viem/tempo'
import { client } from './viem.config'

declare function signInWithGoogle(options: { nonce: string }): Promise<string>

const keyPair = await WebCryptoP256.createKeyPair()
const { credential } = await client.oidc.prove({
  getToken: ({ nonce }) => signInWithGoogle({ nonce }),
  publicKey: keyPair.publicKey,
})
const account = Account.fromZk(credential)
const accessKey = Account.fromWebCryptoP256(keyPair, { access: account })

const keyAuthorization = await account.signKeyAuthorization(accessKey, {
  admin: true, // [!code focus]
  chainId: BigInt(client.chain.id),
})
```

## Best Practices

### Keep One Client ID per Account

The OAuth client ID is part of every address. A user who signs in through another client ID,
such as a separate mobile app, reaches a different account. Share one client ID wherever users
expect the same account.

### Limit What the Access Key Can Do

The access key holds the account's lasting authority, since a credential lasts only minutes. Give
it an expiry, spending limits, and call scopes with
[Set Permissions & Limits](/tempo/guides/access-keys/permissions).
