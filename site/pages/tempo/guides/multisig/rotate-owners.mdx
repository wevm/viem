# Rotate Multisig Owners

## Overview

Use [multisig.updateConfigSync](/tempo/actions/multisig.updateConfigSync) to replace owners or their threshold. The call includes the current config and requires its owner quorum. The returned event contains the new complete config and incremented version.

## Recipes

These recipes assume you have [set up a Tempo client](/tempo) and funded the multisig account.

### Update and Retain the New Config

:::code-group

```ts twoslash [example.ts]
import { Account } from 'viem/tempo'
import { client } from './viem.config'

declare const account: Account.MultisigAccount<import('viem/tempo').MultisigConfig.Config>
const newOwner = Account.fromSecp256k1(
  '0x5de4111afa1a4b94908f83103eb1f1706367c2e68ca870fc3fb9a804cdab365a'
)
const { receipt, account: address, ...config } = await client.multisig.updateConfigSync({
  account,
  current: account.config,
  owners: [{ owner: newOwner.address, weight: 1 }],
  threshold: 1,
})
const updated = Account.fromMultisig(
  { ...config, owners: [newOwner] },
  { address },
)
```

```ts twoslash [viem.config.ts] filename="viem.config.ts"
// [!include ~/snippets/tempo/viem.config.ts:setup]
```

:::

## Best Practices

Persist the stable address and complete config after a successful receipt. The node stores only the commitment. Reusing the old config fails during preparation, and deriving an address from the updated config is invalid.

For distributed signing, include [multisig.updateConfig.call](/tempo/actions/multisig.updateConfig) in a prepared transaction and collect the current owners' approvals.
