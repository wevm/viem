# Upgrade an Existing Account

## Overview

An existing account can become a configurable account in place ([TIP-1113](https://tips.sh/1113)).
It keeps its address, balances, and history, and installs a set of weighted owners.

The account's root key signs a transaction that calls the upgrade, alone or in a batch. After the
upgrade, only the installed owners can authorize the account. The root key is retired permanently.

## Recipes

These recipes assume you have [set up a Tempo client](/tempo).

### Upgrade to a 2-of-2 Account

Sign the upgrade with the root key, then recreate the account from its address and the installed
owners with [`Account.fromConfig`](/tempo/accounts/account.fromConfig).

:::code-group

```ts twoslash [example.ts]
import { Account } from 'viem/tempo'
import { client } from './viem.config'

const root = Account.fromSecp256k1(
  '0xac0974bec39a17e36ba4a6b4d238ff944bacb478cbed5efcae784d7bf4f2ff80'
)
const owner_1 = Account.fromSecp256k1(
  '0x59c6995e998f97a5a0044966f0945389dc9e86dae88c7a8412f4603b6b78690d'
)
const owner_2 = Account.fromSecp256k1(
  '0x5de4111afa1a4b94908f83103eb1f1706367c2e68ca870fc3fb9a804cdab365a'
)

await client.accounts.upgradeSync({ // [!code focus]
  account: root, // [!code focus]
  owners: [ // [!code focus]
    { owner: owner_1.address, weight: 1 }, // [!code focus]
    { owner: owner_2.address, weight: 1 }, // [!code focus]
  ], // [!code focus]
  threshold: 2, // [!code focus]
}) // [!code focus]

const account = Account.fromConfig({ // [!code focus]
  address: root.address, // [!code focus]
  upgrade: { owners: [owner_1, owner_2], threshold: 2 }, // [!code focus]
}) // [!code focus]

const receipt = await client.sendTransactionSync({
  account,
  to: '0xcafebabecafebabecafebabecafebabecafebabe',
})
```


:::

### Grant an Access Key in the Upgrade

The upgrade transaction can carry a key authorization that the root key signs. The access key is
authorized before the upgrade and keeps working after it.

:::code-group

```ts twoslash [example.ts]
import { Account } from 'viem/tempo'
import { client } from './viem.config'

const root = Account.fromSecp256k1(
  '0xac0974bec39a17e36ba4a6b4d238ff944bacb478cbed5efcae784d7bf4f2ff80'
)
const owner = Account.fromSecp256k1(
  '0x59c6995e998f97a5a0044966f0945389dc9e86dae88c7a8412f4603b6b78690d'
)
const accessKey = Account.fromSecp256k1(
  '0x5de4111afa1a4b94908f83103eb1f1706367c2e68ca870fc3fb9a804cdab365a',
  { access: root },
)

const keyAuthorization = await client.accessKey.signAuthorization({ // [!code focus]
  account: root, // [!code focus]
  accessKey, // [!code focus]
}) // [!code focus]

await client.accounts.upgradeSync({
  account: root,
  keyAuthorization, // [!code focus]
  owners: [{ owner: owner.address, weight: 1 }],
  threshold: 1,
})

const receipt = await client.sendTransactionSync({
  account: accessKey,
  to: '0xcafebabecafebabecafebabecafebabecafebabe',
})
```


:::

### Batch the Upgrade with Other Calls

Send [`accounts.upgrade.call`](/tempo/actions/accounts.upgrade#batch-the-upgrade) in `calls`. It may sit
anywhere in the batch, and calls after it run against the upgraded account.

:::code-group

```ts twoslash [example.ts]
import { Account, Actions } from 'viem/tempo'
import { client } from './viem.config'

const root = Account.fromSecp256k1(
  '0xac0974bec39a17e36ba4a6b4d238ff944bacb478cbed5efcae784d7bf4f2ff80'
)
const owner = Account.fromSecp256k1(
  '0x59c6995e998f97a5a0044966f0945389dc9e86dae88c7a8412f4603b6b78690d'
)

const receipt = await client.sendTransactionSync({
  account: root,
  calls: [
    Actions.accounts.upgrade.call({ // [!code focus]
      owners: [{ owner: owner.address, weight: 1 }], // [!code focus]
      threshold: 1, // [!code focus]
    }), // [!code focus]
    { to: '0xcafebabecafebabecafebabecafebabecafebabe' },
  ],
})
```


:::

## Best Practices

### Treat the Upgrade as Permanent

The root key cannot be restored. Existing access keys and vouchers on funded channels keep working,
but the root key can no longer sign new key authorizations, permits, channel opens or top-ups, or act
as a fee payer. Sign those with the configurable account after the upgrade.

[`verifyHash`](/docs/actions/public/verifyHash), [`verifyMessage`](/docs/actions/public/verifyMessage),
and [`verifySiweMessage`](/docs/siwe/actions/verifySiweMessage) return `false` for a signature of
the retired root key. They read the account's config commitment to check, also with `mode: 'eoa'`.

### Upgrade Accounts Without Code

Only accounts without code can be upgraded. An account that is already
configurable rotates its owners with [`accounts.updateConfig`](/tempo/actions/accounts.updateConfig).
