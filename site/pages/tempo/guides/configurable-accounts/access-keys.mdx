# Authorize an Access Key

## Overview

An owner quorum can authorize an access key. The access key then signs later transactions for
the configurable account, subject to the authorization's expiry, scopes, and spending limits. Owners
can sign locally or coordinate approvals through a shared account store.

A configurable account can also act as the access key of another account
([TIP-1111](https://tips.sh/1111)). Its owner quorum then signs transactions for that parent
account, within the grant's limits.

## Recipes

These recipes assume you have [set up a Tempo client](/tempo).

### Local Signing

:::code-group

```ts twoslash [example.ts]
import { Account, P256 } from 'viem/tempo'
import { client } from './viem.config'

// 1. Create an account with enough local owners for quorum.
const owner_1 = Account.fromSecp256k1(
  '0xac0974bec39a17e36ba4a6b4d238ff944bacb478cbed5efcae784d7bf4f2ff80'
)
const owner_2 = Account.fromSecp256k1(
  '0x59c6995e998f97a5a0044966f0945389dc9e86dae88c7a8412f4603b6b78690d'
)
const account = Account.fromConfig({
  address: 'infer',
  owners: [owner_1, owner_2],
  threshold: 2,
})

// 2. Create and authorize an access key for the account.
const accessKey = Account.fromP256(P256.randomPrivateKey(), {
  access: account,
})

const keyAuthorization = await client.accessKey.signAuthorization({
  account,
  accessKey,
})

// 3. Submit the authorization with the access key's first transaction.
const { receipt } = await client.token.transferSync({
  account: accessKey,
  amount: 100n,
  keyAuthorization,
  to: '0xcafebabecafebabecafebabecafebabecafebabe',
  token: '0x20c0000000000000000000000000000000000001',
})
```


:::

If the account is uninitialized, the authorization carries its initial config and this first
access-key transaction initializes the account. If the account is already initialized,
[`signAuthorization`](/tempo/actions/accessKey.signAuthorization) resolves its current version
before the owners sign.

### Coordinated Signing

Use coordinated signing when owners approve from separate clients or processes. The first owner
defines the authorization and receives an operation hash. Later owners approve the stored
authorization by that hash.

:::code-group

```ts twoslash [example.ts]
import { Account, P256 } from 'viem/tempo'
import { client } from './viem.config'

// 1. Create the owners and configurable account.
const owner_1 = Account.fromSecp256k1(
  '0xac0974bec39a17e36ba4a6b4d238ff944bacb478cbed5efcae784d7bf4f2ff80'
)
const owner_2 = Account.fromSecp256k1(
  '0x59c6995e998f97a5a0044966f0945389dc9e86dae88c7a8412f4603b6b78690d'
)
const account = Account.fromConfig({
  address: 'infer',
  owners: [owner_1.address, owner_2.address],
  threshold: 2,
})
const accessKey = Account.fromP256(P256.randomPrivateKey(), {
  access: account,
})

// 2. Store the first owner's approval.
const pending = await client.accessKey.signAuthorization({
  accessKey,
  account,
  owner: owner_1,
})

// 3. Complete the quorum using the operation hash.
const keyAuthorization = await client.accessKey.signAuthorization({
  hash: pending.hash,
  owner: owner_2,
})
if (keyAuthorization.status !== 'success') throw new Error('Expected quorum.')

// 4. Submit the authorization with the access key's first transaction.
const { receipt } = await client.token.transferSync({
  account: accessKey,
  amount: 100n,
  keyAuthorization,
  to: '0xcafebabecafebabecafebabecafebabecafebabe',
  token: '0x20c0000000000000000000000000000000000001',
})
```

:::

### Use the Authorized Key Again

After the authorization is registered, prepare future requests under the access key without
passing `keyAuthorization` again.

```ts twoslash
import { Account, P256 } from 'viem/tempo'
import { client } from './viem.config'

declare const account: Account.ConfigurableAccount

// 1. Recreate the access key for the authorized account.
const accessKey = Account.fromP256(P256.randomPrivateKey(), {
  access: account,
})

// 2. Use it without resubmitting the registered authorization.
const { receipt } = await client.token.transferSync({
  account: accessKey,
  amount: 100n,
  to: '0xcafebabecafebabecafebabecafebabecafebabe',
  token: '0x20c0000000000000000000000000000000000001',
})
```

### Stateless Approvals

Without a shared store, prepare the authorization once, collect every owner signature over its
`signPayload`, and pass the complete approval set to `signAuthorization`.

```ts twoslash
import { Account, P256 } from 'viem/tempo'
import { client } from './viem.config'

const owner_1 = Account.fromSecp256k1(
  '0xac0974bec39a17e36ba4a6b4d238ff944bacb478cbed5efcae784d7bf4f2ff80'
)
const owner_2 = Account.fromSecp256k1(
  '0x59c6995e998f97a5a0044966f0945389dc9e86dae88c7a8412f4603b6b78690d'
)
const account = Account.fromConfig({
  address: 'infer',
  owners: [owner_1.address, owner_2.address],
  threshold: 2,
})
const accessKey = Account.fromP256(P256.randomPrivateKey(), {
  access: account,
})

// 1. Prepare the authorization once.
const authorization = await client.accessKey.prepareAuthorization({
  account,
  accessKey,
})

// 2. Collect every owner signature over the same payload.
const signatures = await Promise.all(
  [owner_1, owner_2].map((owner) =>
    owner.sign({ hash: authorization.signPayload })
  )
)

// 3. Assemble the complete key authorization.
const keyAuthorization = await client.accessKey.signAuthorization({
  ...authorization,
  signatures,
})
```

### Use a Configurable Account as an Access Key

Pass `access` to [`Account.fromConfig`](/tempo/accounts/account.fromConfig) to make a configurable
account the access key of a parent account. The parent authorizes the configurable account's address with key type `configurable`,
and the configurable account's owners then sign as the parent.

:::code-group

```ts twoslash [example.ts]
import { Account } from 'viem/tempo'
import { client } from './viem.config'

// 1. Create the parent account and the configurable account for its access key.
const treasury = Account.fromSecp256k1(
  '0xac0974bec39a17e36ba4a6b4d238ff944bacb478cbed5efcae784d7bf4f2ff80'
)
const owner_1 = Account.fromSecp256k1(
  '0x59c6995e998f97a5a0044966f0945389dc9e86dae88c7a8412f4603b6b78690d'
)
const owner_2 = Account.fromSecp256k1(
  '0x5de4111afa1a4b94908f83103eb1f1706367c2e68ca870fc3fb9a804cdab365a'
)
// 2. Create the configurable account as an access key of the parent.
const accessKey = Account.fromConfig( // [!code focus]
  { owners: [owner_1, owner_2], threshold: 2 }, // [!code focus]
  { access: treasury }, // [!code focus]
) // [!code focus]

// 3. Authorize it from the parent account.
await client.accessKey.authorizeSync({
  account: treasury,
  accessKey, // [!code focus]
  limits: [
    { token: '0x20c0000000000000000000000000000000000001', limit: 2_000_000_000n },
  ],
})

// 4. The team's owner quorum signs as the parent account.
const { receipt } = await client.token.transferSync({
  account: accessKey, // [!code focus]
  amount: 100n,
  to: '0xcafebabecafebabecafebabecafebabecafebabe',
  token: '0x20c0000000000000000000000000000000000001',
})
```

```ts twoslash [viem.config.ts] filename="viem.config.ts"
// [!include ~/snippets/tempo/viem.config.ts:setup]
```

:::

The access key signs a keychain signature that wraps the team's owner approvals. Pass
`keyAuthorization` alongside `access` to submit a signed authorization with the first
transaction instead. Requires the T14 hardfork.

## Best Practices

### Keep Owner Signers Separate

Each owner should validate the configurable account, access key, chain, expiry, scopes, and spending
limits before approving an authorization.

### Restrict the Access Key

Set an expiry, call scopes, and spending limits that match the key's purpose. Revoke the key when
it is no longer needed.

### Revoke Grants Explicitly

Owner updates keep every access key grant, in both directions. To cut off an access key, or a
configurable account acting as one, revoke it with
[`accessKey.revoke`](/tempo/actions/accessKey.revoke).
