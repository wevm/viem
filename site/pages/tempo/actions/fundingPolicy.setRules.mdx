# `fundingPolicy.setRules`

Replaces a policy's routes and maximum slippage. A current administrator must send the transaction. Updating rules invalidates earlier encoded rules.

## Usage

:::code-group

```ts twoslash [example.ts]
import { Addresses, FundingSource } from 'viem/tempo'
import { client } from './viem.config'

const { rulesHash, receipt } = await client.fundingPolicy.setRulesSync({
  policyId: 1n,
  rules: {
    maxSlippageBps: 50,
    sources: {
      [Addresses.pathUsd]: [{
        target: Addresses.dexFundingSource,
        data: FundingSource.encodeData({ tokenIn: Addresses.alphaUsd }),
      }],
    },
  },
})
// @log: { rulesHash: '0x...', receipt: { ... } }
```

```ts twoslash [viem.config.ts] filename="viem.config.ts"
// [!include ~/snippets/tempo/viem.config.ts:setup]
```

:::

The asynchronous `setRules` variant returns a transaction hash. Use `Actions.fundingPolicy.setRules.extractEvent(receipt.logs)` to read the updated rules from its event.

## Return Type

### setRules

```ts
type ReturnType = Hash
```

### setRulesSync

```ts
type ReturnType = {
  policyId: bigint
  updater: Address
  rulesHash: Hex
  rules: { maxSlippageBps: number; routes: FundingPolicy.Route[] }
  receipt: TransactionReceipt
}
```

## Parameters

### policyId

- **Type:** `bigint`

Funding policy ID.

### rules

- **Type:** `FundingPolicy.Rules`

Replacement token-keyed source routes and maximum aggregate slippage.
