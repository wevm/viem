# `funding.setPolicyRules`

Replaces a policy's routes and maximum slippage. A current administrator must send the transaction. Updating rules invalidates earlier encoded rules.

## Usage

:::code-group

```ts twoslash [example.ts]
import { Addresses, FundingSource } from 'viem/tempo'
import { client } from './viem.config'

const { rulesHash, receipt } = await client.funding.setPolicyRulesSync({
  policyId: 1n,
  rules: {
    maxSlippageBps: 50,
    sources: {
      [Addresses.pathUsd]: [FundingSource.dex({ tokenIn: Addresses.alphaUsd })],
    },
  },
})
// @log: { rulesHash: '0x...', receipt: { ... } }
```

```ts twoslash [viem.config.ts] filename="viem.config.ts"
// [!include ~/snippets/tempo/viem.config.ts:setup]
```

:::

The asynchronous `setPolicyRules` variant returns a transaction hash. Use `Actions.funding.setPolicyRules.extractEvent(receipt.logs)` to read the updated rules from its event.

### Standalone Action

:::code-group

```ts twoslash [example.ts]

import { client } from './viem.config'

```

## Parameters

### policyId

- **Type:** `bigint`

Funding policy ID.

### rules

- **Type:** `FundingPolicy.Rules`

Replacement token-keyed source routes and maximum aggregate slippage.

#### enforceOrder

- **Type:** `boolean`
- **Default:** `false`

Set `rules.enforceOrder` to `true` to require funding sources to follow their policy order. When omitted or `false`, allowed sources can be used in any order.

```ts twoslash
import { Actions } from 'viem/tempo'
// ---cut---
Actions.funding.setPolicyRules.call({
  policyId: 1n,
  rules: {
    enforceOrder: true, // [!code focus]
    maxSlippageBps: 100,
    sources: {},
  },
})
```
